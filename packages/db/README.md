# @sotf/db

The data contract of SOTF Mods v2 (PLAN §6): the **same production PostgreSQL 16** as the legacy
API, extended only with **additive** migrations. It ships:

- the Drizzle schema of the 16 legacy tables (`src/schema/legacy/*`, with the 4 `drizzle-kit pull`
  defects fixed) and of every v2 table (`src/schema/v2/*`), plus relations;
- hand-written SQL migrations (`migrations/`) with a tested **down** file each, their runner and a
  SQL linter;
- the **legacy ⊆ v2 guard** against a frozen snapshot of the legacy catalog;
- `createDb` / `withTx`, and test helpers (`@sotf/db/testing`).

## Commands

| Command | What it does |
|---|---|
| `pnpm db:migrate` | Lint → advisory lock → guard (pre) → pending migrations → pg-boss schema → guard (post). Idempotent. |
| `pnpm db:migrate --dry-run` | Prints the plan; changes nothing. |
| `pnpm db:migrate --to <name>` · `--strict` · `--no-pgboss` | Stop at a migration · exit 2 if something is deferred · skip pg-boss. |
| `pnpm db:migrate status` | Applied / pending migrations. |
| `pnpm db:migrate down --to <name> [--confirm <db>]` | Rolls back every migration after `<name>` (a non-local database needs `--confirm`). |
| `pnpm db:guard [--json]` | Read-only superset check; exit 1 on drift. Safe against production. |
| `pnpm db:baseline --mark-applied` | On a database that already has the legacy schema: records `0000` without running it, after the guard passes. |
| `pnpm --filter @sotf/db db:lint-sql` | Lints the migrations without a database. |
| `pnpm --filter @sotf/db gen` | Regenerates `0025_seed_taxonomy` from `src/seed/taxonomy.ts` (part of `pnpm gen`). |
| `pnpm --filter @sotf/db db:catalog:snapshot [--check]` | Re-freezes `src/guard/legacy-catalog.json` from `0000` (Docker). |
| `pnpm --filter @sotf/db db:baseline:generate [--check]` | Regenerates `0000` with `prisma@6.19.0 migrate diff` (network). |

Environment (validated by `src/env.ts`; a root `.env` is loaded when present):
`MIGRATIONS_DATABASE_URL` (owner, migrate task; falls back to `DATABASE_URL` locally),
`DATABASE_URL` (app role; used by `db:guard`), `MIGRATIONS_DIR`, `PGBOSS_SCHEMA` (default `pgboss`).

## Using it

```ts
import { createDb, mod, withTx } from '@sotf/db';
import { eq } from 'drizzle-orm';

const { db, close } = createDb({ connectionString: env.DATABASE_URL, max: 10, applicationName: 'sotf-api' });
const found = await db.query.mod.findFirst({ where: eq(mod.slug, 'stackmod'), with: { versions: true, user: true } });
await withTx(db, async (tx) => {
  await tx.update(mod).set({ status: 'published' }).where(eq(mod.id, found!.id)); // trigger syncs isApproved
});
```

- TypeScript names equal database names, except `"Mod"."mod_id"` → `manifestId`.
- Legacy `timestamp(3)` columns hold UTC wall-clock values and map to `Date`s (`mode: 'date'`); raw `pg`
  queries through the pool parse them as UTC too. Every connection runs with `TimeZone=UTC`.
- Legacy `"updatedAt"` columns follow Prisma's `@updatedAt`: Drizzle sets them on every update
  (`$onUpdate`). Jobs that must not touch them (PLAN §6.8 `legacy.counters`) pass
  ``updatedAt: sql`"updatedAt"` `` explicitly.
- uuid primary keys default to UUIDv7 on insert (`$defaultFn`); identity columns are generated by
  the database.

## Rules for migrations (enforced by the linter and the guard)

Numbering: WP-10 owns `0000`–`0099`; W2 uses up to `1299`; W3 `1300–1399`, W4 `1400–1499` … W10
`2000–2099` (PLAN §12.1). Later work packages add `migrations/<NNNN>_<wp-id>_<slug>.sql` + `.down.sql`
and their Drizzle declarations in `src/schema/ext/<wp-id>.ts`. Drizzle cannot extend a table declared
in another file, so a new column on an existing table also needs a line in its table file under
`src/schema/{legacy,v2}/` (see docs/backlog/WP-10.md). Never edit an applied migration.

- Every file runs in its own transaction with `lock_timeout = 3s` and `statement_timeout = 60s`
  (`-- sotf:lock-timeout:` / `-- sotf:statement-timeout:` override them). Lock timeouts are
  retried with backoff.
- New columns on legacy tables: `NULL`, or `NOT NULL DEFAULT <constant>`; no inline constraints.
  CHECK / FOREIGN KEY on legacy tables are added `NOT VALID` and validated in a later file.
- Indexes on existing tables: `CREATE [UNIQUE] INDEX CONCURRENTLY IF NOT EXISTS`, one per file,
  marked `-- sotf:no-transaction`. A failed build leaves an INVALID index that the runner drops and
  rebuilds.
- Indexes that depend on a backfill carry `-- sotf:precondition: <boolean SQL>`; while it is false
  the migration is **deferred** (reported, not recorded) and retried on the next run. Today:
  `0038` (unique follows, after B5), `0039` (unique versions, Q-P6), `0040` (one latest version),
  `0045` (unique `emailNormalized`, after B6 with 0 collisions).
- Forbidden on legacy objects: `DROP`, `RENAME`, type changes, `SET/DROP NOT NULL`, dropping or
  changing an existing default, `UPDATE` of legacy columns, `DELETE`/`TRUNCATE` (a down file may
  delete rows it created with `-- sotf:allow-legacy-delete: <reason>`). Also forbidden anywhere:
  `CASCADE`, transaction control, `GRANT`/`REVOKE` (see `ops/sql/roles.sql`).
- New foreign keys that point at legacy rows are `ON DELETE CASCADE` (NOT NULL) or `SET NULL`
  (nullable): v2 data must never block a legacy delete path.
- Every migration has a `.down.sql`; the integration tests roll everything back to the baseline,
  compare the catalog with the snapshot and re-apply.

## What is where

| Path | Content |
|---|---|
| `legacy/schema.prisma` | Literal copy of `sotf-mods-api@e0606b6` `prisma/schema.prisma` (baseline source). |
| `migrations/0000_legacy_baseline.sql` | Legacy DDL (Prisma 6.19); recorded, never executed, in production. |
| `migrations/0001`–`0020` | Extensions + `sotf_unaccent`, `updatedAt` defaults, the §6.3 columns, the §6.4 tables, the §6.6 triggers. |
| `migrations/0025_seed_taxonomy` | 12 categories (13 locales, icons, `legacySlugs`; `qol` retired), 40 curated tags, RedLoader 0.8.6. Inserted ids are recorded in `"MigrationRun"` so the down removes only them. |
| `migrations/0030`–`0048` | §6.5 indexes (`CONCURRENTLY`). `0090`/`0091` validate the `NOT VALID` constraints. |
| `src/migrate/` | File loader (directives, checksums), lexer, linter, runner. |
| `src/guard/` | Catalog introspection, comparison, `legacy-catalog.json`, Drizzle ↔ catalog comparison. |
| `src/schema/` | Drizzle tables; `_index.gen.ts` is generated by `pnpm gen`. |
| `src/testing.ts` | `startTestDb()` (Testcontainers `postgres:16-alpine`, template clone per call; or `SOTF_TEST_DATABASE_URL`), `createFactories(db)`. |

## Taxonomy rule for consumers

A category with `retiredAt` set is no longer part of the v2 taxonomy but stays valid for its mods:
it resolves to the active category whose `legacySlugs` contains its slug (`qol` → `quality-of-life`).
Mod categories are `type = 'Mod'`; build categories (`type = 'Build'`) are untouched.

## Tests

- `pnpm --filter @sotf/db test`: lexer, file loader, linter (seeded `DROP` and every rule), guard
  comparison, the 4 Drizzle fixes, Drizzle ↔ legacy snapshot, seed data and generated SQL.
- `pnpm --filter @sotf/db test:int` (Docker): migrate from empty on PG16 and again (no-op), dry
  run, concurrent runs, down to the baseline and back, production-like database (baseline
  recording, deferred indexes, untouched legacy data, seed over legacy categories), drift abort,
  lint refusal, checksum drift, INVALID index rebuild, Drizzle ↔ live catalog, triggers,
  `ops/sql/*` (roles, kill switch, audit) and the CLIs.
