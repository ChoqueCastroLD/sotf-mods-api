# WP-80 backlog (Basecamp)

Changes outside WP-80's paths, or gaps of other work packages found while building Basecamp. One line per item: what · where · why.

- **`recharts` dependency added** · `apps/web/package.json` (WP-00) + `pnpm-lock.yaml` · `"recharts": "catalog:"` (3.10.1 from the catalog); the Basecamp charts need it and PLAN §12.1 lets a WP pin a new dependency in its package.json. It ships as its own lazy chunk (`features/basecamp/charts/Charts.tsx`, ~90 KB br), never in a route chunk.
- [x] resolved by final-console-creator: **Sidebar entry for the inbox** · `apps/web/src/console/lib/navigation.ts` + `packages/i18n/messages/console/**` (WP-34) · add `/basecamp/inbox` («Inbox», icon `Inbox`) to the Basecamp section; today it is reachable from the summary header, «Needs attention», the compatibility tab and the editor, but not from the sidebar. (The drafts entry is already asked for in docs/backlog/WP-74.md.)
- [x] resolved by wire-api (StudioModDTO.media { thumbnailMediaId, gallery[{ mediaId, url }] }): **Media ids of the owner view** · `packages/contracts/src/studio.ts` `StudioModDTO` + `packages/core/src/publishing/studio.ts` (WP-40) · expose `thumbnailMediaId` and `gallery[].mediaId` (null for legacy rows) in the owner view. The editor parses the id from the variant URL (`…/media/{uuid}/{w}.webp`); a legacy image adopted by B15 but not processed yet has no parseable id, so it is shown locked (cannot be reordered or removed) and a legacy cover cannot be removed until processed.
- [x] resolved by wire-api (owner versions carry changelogMd (OwnerVersionDTO)): **Changelog source of owner versions** · `VersionDTO` in owner responses (WP-40) · add `changelogMd` to the versions of `StudioModDTO`; without the Markdown source the editor cannot offer «edit changelog» (`UpdateVersionBody.changelogMd` exists but only HTML is returned).
- [x] resolved by wire-api (AnalyticsDTO.seriesByVersion): **Per-version daily series** · `AnalyticsDTO` (WP-52) · `byVersion` is one total per version, so «descargas por versión (barras apiladas)» is drawn as one bar per version; a `seriesByVersion: [{ day, version, downloads }]` (≤ 8 + other) would allow the stacked daily bars of research/03 §6.9.
- [x] resolved by wire-api (InboxQuery.modId): **Inbox filter by mod** · `InboxQuery` (WP-52) · add `modId` so «Needs attention → N unanswered questions on X» can open the inbox filtered to that mod; today it opens the inbox filtered by kind.
- **Live events for downloads and kits** · `packages/contracts/src/notifications.ts` / `events.ts` (WP-43/WP-20) · there is no SSE event for downloads (they are polled from `GET /mods/:id/live` every 60 s for the five busiest mods) nor a notification when a kit adds my mod («kits que añadieron tu mod», PLAN §7.5); a `kit.added_my_mod` notification type (in-app only, grouped) would feed the «Live» panel through the existing stream.
- [x] resolved by wire-api (mod owners commenting on their own mod are exempt from Turnstile): **Turnstile in inline replies** · `features/basecamp/InboxScreen.tsx` / `CreateCommentBody.turnstileToken` (WP-41) · accounts younger than 24 h need a Turnstile token to comment; the inbox composer has no widget, so such a (rare) creator gets the «TURNSTILE_REQUIRED» toast and must reply from the public page. Exempting mod owners replying on their own mod would remove the gap.
- [x] resolved by final-console-creator: **Domain components copy** · `components/DomainI18nBridge.tsx` (WP-34, already in docs/backlog/WP-34.md) · `ChartFigure` («View as table»), `StatTile` deltas and `BadgeStamp` («Locked») stay English in the console until the `ui-domain` namespace is compiled into `@sotf/i18n`.
