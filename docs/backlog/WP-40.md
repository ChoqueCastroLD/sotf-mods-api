## Decisions to confirm

- **Draft kinds** · `"ModDraft"."kind"` only allows `mod | build` (CHECK of 0013); a `version` draft is stored with the target's kind and `modId` set, and served as `kind: 'version'`.
- **Draft limit** · 20 open drafts per user (CONFLICT beyond).
- **Author transitions** · published ⇄ unlisted ⇄ archived (archive with an optional published successor), rejected → pending (`/publish` = resubmit, the rejected latest version goes back to `pending`), `request-removal` opens one `Report` (`reason = other`, details prefixed `[author removal request]`) and does not change the status.
- **Yank** · a yanked version keeps its URL; the latest moves to the highest remaining `active` version (legacy `isLatest`, `latestVersion` and CSV follow). Unyank restores it.
- **New versions carry dependencies** · without wizard-declared dependencies, the optional/conflicting (and ranged) dependencies of the current latest version are carried over; manifest dependencies are always `required`.
- **Builds depend on `BuildShare`** · every build version gets a required `ModDependency` on manifest id `BuildShare` (T0-24); the legacy CSV stays empty for builds, as the legacy site wrote it.
- **Legacy gallery rows without `Media`** · `PUT /studio/mods/:id/media` never deletes `ModImage` rows whose `mediaId` is NULL (not yet adopted by B15): they cannot be referenced by id.
- **`latestVersionSize`** · the legacy column is left untouched (the legacy API never wrote it either).
- **Publishing sanctions** · an active `ban` or `upload_mute` sanction blocks submissions and new versions (403).
- **Description images of pending mods** · replicated when the mod is published (`mod.published` / `mod.status_changed` → `published`) or its description is edited.
