- **Known limit, not fixed in the hotfix**: the legacy API still trusts `?ip=` from any caller (it did before as well) and has no download rate limit. v2 fixes this with `ipHash`, `X-Internal-Auth` between web and API, and a non-counting limit (WP-31).
- **User (deploy, required before the API)**: create the Cloudflare Response Header Transform Rule on `r2.sotf-mods.com` (`http.request.uri.path.extension in {"json" "zip"}` → `Content-Disposition: attachment`). Without it, Build `.json` files open as text in a new tab after the 302 (R2 sends no `Content-Disposition`). Steps and `curl -I` checks are in `ops/legacy-hotfix/README.md` (Despliegue, step 0).
- **Known limit (cosmetic), WP-84**: after the 302, browsers save files with the timestamp-prefixed R2 key (`1766549349465_Regi's Modding Library.zip`) instead of `<Name> <version>.<ext>`. v2 fixes it with the in-place R2 metadata rewrite (B17: `Content-Disposition` with `filename`). The alternative (Cloudflare Snippet/Worker with `?dl=`) is not part of the hotfix.
- **Known limit, v2**: the legacy session token stays in `localStorage` and there is no `Content-Security-Policy`; the API stores user text unescaped (it is escaped at render time). v2 (cookie session, CSP) closes these.
