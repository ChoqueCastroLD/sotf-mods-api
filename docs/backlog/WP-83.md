# WP-83 backlog (Admin UI)

- **Admin category list lacks `retiredAt` and `hubIntro`** · `packages/contracts/src/admin.ts` + `packages/core/src/admin/taxonomy.ts` (WP-51) · `PUT /admin/categories/:id` replaces `hubIntro` (default `{}`) but no read returns it, so editing a category from the UI wipes a stored hub intro; retired categories are only told apart by diffing with the public list. Add both fields to the `GET /admin/categories` items (additive); the UI already reads them when present (`CategoryExtras`).
- **Admin tag list lacks `description` and `sortOrder`** · same files (WP-51) · `PUT /admin/tags/:id` replaces both with defaults; return them in `GET /admin/tags` (the UI prefills them when present, `TagExtras`).
- **Recategorize suggestions lack the mod's current tags** · `RecategorizeResultDTO` (WP-51) · `tagSlugs` in a change replaces the whole tag set, so the UI reads current tags through the public `GET /mods/:id` and skips tag changes for non-public mods. Add `currentTags: string[]` to each suggestion (additive) and switch `recategorize.ts#planChanges` to it.
- **Game build / ecosystem notes only come back as HTML** · `GameBuildDTO.notesHtml`, `EcosystemEntryDTO.noteHtml` (WP-50) · the admin forms cannot prefill the Markdown source; they offer «leave empty to keep» / «remove notes». Return `notesMd`/`noteMd` in the admin reads.
- **CSV contract for WP-84** · `tooling/migration/backfills-r2/**` (WP-84) · `suggest-categories.ts` should write `modId,manifestId,name,currentCategory,categorySlug,tagSlugs,confidence,reason` (`tagSlugs` joined with `|`, confidence 0–1) — the format the import reads and «Export CSV» writes (`apps/web/src/console/features/admin/README.md`).
- **Acceptance tests pending (dev-only mode)** · `pnpm e2e --grep @admin` and axe on the admin screens are left to the testing phase.
